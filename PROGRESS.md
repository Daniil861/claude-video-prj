### 2. Аутентификация и главная страница (`18a00ea`)

**API:**

| Эндпоинт                    | Что делает                                                                                        |
| --------------------------- | ------------------------------------------------------------------------------------------------- |
| `POST /api/auth/login`      | `{ email, password }` → `{ accessToken, user }`, 401 при неверных данных, 400 при невалидном теле |
| `GET /api/auth/me`          | Текущий пользователь по `Authorization: Bearer <jwt>`                                             |

- `src/auth/` — `AuthService` (bcrypt + `@nestjs/jwt`), свой `JwtAuthGuard` (без passport), декоратор `@CurrentUser()`, `LoginDto`.

- Глобальный `ValidationPipe` (`whitelist`, `forbidNonWhitelisted`).

**Web:**

- `/auth/login` — server action `loginAction`: zod-валидация → Nest → httpOnly cookie → `redirect('/')`. Ошибка через `useActionState`, email сохраняется после неудачной попытки (с § 10 форма не сбрасывается вовсе).
- `/` — server component: приветствие с email, счётчик встреч, 3 последние встречи, «Создать встречу», «Выйти».
- `src/middleware.ts` — проверяет подпись и срок JWT через `jose`, удаляет недействительную cookie.
- `/auth/register`, `/meetings/new` — заглушки (регистрация сделана в § 9).
- `src/lib/api.ts` — серверный клиент к Nest. **Не импортировать из клиентских компонентов**: токен не должен попадать в браузер.

### 5. Переход на Postgres через Prisma 7

Дизайн и причины — в [docs/superpowers/specs/2026-09-02-prisma-migration-design.md](docs/superpowers/specs/2026-09-02-prisma-migration-design.md).

Оба хранилища в памяти заменены на Postgres. HTTP-контракт не изменился ни в одной точке.

- `prisma/schema.prisma` — модели `User` и `Meeting` с FK и `onDelete: Cascade`, индекс `[ownerId, startsAt]`, `email @unique`.
- `src/prisma/` — `PrismaService extends PrismaClient` через driver adapter `@prisma/adapter-pg`; `PrismaModule` помечен `@Global()`.
- `UsersService` и `MeetingsService` сохранили публичные методы и стали асинхронными. Контроллеры получили `Promise<...>` в возвращаемом типе — больше ничего.
- Сид уехал из `onModuleInit` в `prisma/seed.ts` (идемпотентный `upsert` по фиксированным id). Те же аккаунты и встречи, что раньше.
- E2E гоняются против отдельной БД `video_meetings_test`; `test/global-setup.ts` сам накатывает миграции, чистит таблицы и засевает их.
- `meetings.service.spec.ts` переехал в `test/meetings.service.e2e-spec.ts` — теперь это интеграционный тест против реального SQL.
- Итог по тестам: **8 unit** (БД не нужна) и **28 e2e** против тестовой БД.

**Что поймали тесты.** `toPublicUser` строился на `Omit<User, 'passwordHash'>` — и появившаяся в таблице колонка `createdAt` сразу потекла в ответы API. Теперь `PublicUser` — явный `Pick`, а не вычитание поля: новая колонка не попадёт в ответ молча.

### 6. Встречи на API: создание, список, одна по id (TDD)

Сначала написаны 22 e2e-теста в `apps/api/test/meetings.e2e-spec.ts`; красный прогон — 18 падений (404 на `POST` и `GET /:id`, список обрезан до трёх). Затем реализация. Тесты `GET /api/meetings` переехали туда же из `auth.e2e-spec.ts`. Всего e2e: 47.

| Эндпоинт                    | Что делает                                                                                      |
| --------------------------- | ----------------------------------------------------------------------------------------------- |
| `POST /api/meetings`        | `{ title, date, participants: string[], durationMinutes? }` → 201 и встреча; 400, 401           |
| `GET /api/meetings?limit=N` | Без `limit` — **все** встречи пользователя (раньше по умолчанию было 3); с `limit` — от 1 до 50 |
| `GET /api/meetings/:id`     | Встреча пользователя; 404 и для несуществующей, и для чужой                                     |

- Миграция `add_meeting_participants`: колонка `Meeting.participants TEXT[] DEFAULT []`. Сид не менялся — у засеянных встреч участников нет.
- `CreateMeetingDto`: `date` — строгий ISO 8601, участники — массив email (пустой допустим), `durationMinutes` — необязательное целое ≥ 1, по умолчанию 30. `ownerId` в теле даёт 400 (`forbidNonWhitelisted`).
- Участники приводятся к нижнему регистру, дубли убираются.
- Главная не пострадала от смены умолчания: она уже явно запрашивает `?limit=3`.
- Тест «404 для чужой встречи» проверен мутацией: без фильтра по `ownerId` он падает с 200.
- Форма `/meetings/new` в web всё ещё заглушка.

### 9. Страница регистрации на HeroUI

- `/auth/register` — рабочая форма вместо заглушки: email, пароль, повтор пароля. `registerAction` → `POST /api/auth/register` → httpOnly cookie → `redirect('/')`, то есть после регистрации пользователь сразу вошёл.
- Ошибки: zod — под своими полями; 409 от API — под полем email («Этот email уже зарегистрирован»); прочие ошибки API — `Alert`. Email сохраняется после неудачной попытки (поведение форм переделано в § 10).
- `confirmPassword` проверяется только в action и в API не уходит — контракт `{ email, password }` не менялся.
- Оформление: общий `app/auth/layout.tsx` (фон с градиентом в цвет `--accent`, логотип) для входа и регистрации; общая карточка `auth-card.module.css`. Поля с иконками (`InputGroup`), показ/скрытие пароля (`PasswordField`), индикатор надёжности (`Meter`, подсказка — правило API только длина ≥ 6).

- Новая зависимость `@gravity-ui/icons` — иконки из документации HeroUI.

### 10. UI/UX-ревью форм входа и регистрации

Проверено в браузере через Playwright MCP (1280px и 375px, светлая и тёмная тема), затем исправлено:

- **Ошибки сбрасываются при правке поля.** Раньше серверная ошибка висела до следующей отправки, а индикатор надёжности пароля прятался за ней.
- **Пароли не стираются после ошибки** (несовпадение, 409, 401). Отправка идёт через `onSubmit` + `startTransition`, а не через `<form action>`, после которого React сбрасывает форму. `action` оставлен фолбэком до гидратации — иначе форма ушла бы GET с паролем в URL.
- **Клиентская валидация теми же правилами, что в action**: схемы вынесены в `features/auth/schemas.ts`. Ошибка — после ухода с непустого поля или после попытки отправки, дальше обновляется на ввод. Несовпадение паролей видно сразу, а не после исправления остальных полей.
- **Фокус на первое неверное поле** после неудачной отправки — ошибку слышно в скринридере.
- **Поля видны на карточке**: `InputGroup variant="secondary"`; у `primary` фон совпадал с карточкой, в тёмной теме поле было невидимо.
- Мелочи: зона нажатия «показать пароль» увеличена до 44px+ без роста поля; ошибка выровнена по подсказке (у `FieldError` HeroUI свой отступ); «Повторите пароль» в ошибке → «Введите пароль ещё раз»; `text-wrap: pretty` у подзаголовка.
- Вход приведён к виду регистрации: те же `EmailField`/`PasswordField` с иконками и показом пароля, кнопка `lg`, тот же хук `useAuthForm`.
- `email` убран из `LoginState`/`RegisterState`: форма больше не сбрасывается, восстанавливать нечего.
- Проверено в браузере против живого API: пустая отправка, несовпадение паролей, успешная регистрация, 409 и сброс ошибки после правки email, 401 на входе.

## Принятые решения

| Решение                                                                         | Почему                                                                                                                                                                                                                             |
| ------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ~~Данные в памяти, а не БД~~ → **Postgres через Prisma**                        | Было временным решением «начать без Docker». Отменено 2026-09-02: расчёт на замену внутренностей сервисов оправдался — контроллеры получили только `Promise` в типах                                                               |
| Prisma 7, а не 6                                                                | Текущий стабильный мажор. Цена — `prisma.config.ts` вместо `url` в схеме и обязательный driver adapter (`@prisma/adapter-pg` + `pg`)                                                                                               |
| Сервисы без отдельного слоя репозиториев                                        | `UsersService`/`MeetingsService` уже являются границей хранилища; второй слой был бы дублем поверх двух строк логики                                                                                                               |
| Отдельная БД `video_meetings_test` для e2e                                      | Прогон чистит таблицы; на общей БД он стирал бы данные, наклацанные в браузере                                                                                                                                                     |
| `PublicUser` — явный `Pick`, а не `Omit`                                        | Новая колонка в таблице иначе молча утекает в ответ API — ровно это и произошло с `createdAt`                                                                                                                                      |
| Фиксированные id в сиде при `cuid()` по умолчанию                               | Проверки в тестах опираются на `usr_1`; иначе пришлось бы править тесты, не связанные с задачей                                                                                                                                    |
| JWT в httpOnly cookie, а не localStorage                                        | Токен недоступен браузерному JS; главная — server component, без вспышки неавторизованного состояния                                                                                                                               |
| Server Actions вместо route handlers в Next                                     | Меньше слоёв: нет промежуточного `/api/...` в Next                                                                                                                                                                                 |
| Свой `JwtAuthGuard` вместо passport-jwt                                         | ~20 строк вместо трёх зависимостей и стратегий                                                                                                                                                                                     |
| Middleware проверяет подпись и срок, а не наличие cookie                        | Иначе просроченный токен зацикливает редиректы: гард пускает → страница ловит 401 → снова на логин                                                                                                                                 |
| Общие ESLint/TS-конфиги в `packages/`                                           | Одни правила на оба приложения                                                                                                                                                                                                     |
| Env по приложению, а не один корневой                                           | Next не читает корневой `.env`                                                                                                                                                                                                     |
| Регистрация принимает только email и пароль                                     | Контракт тот же, что у login; обязательное `name` в `User` заполняется локальной частью email                                                                                                                                      |
| Дубль email — 409, а не 400                                                     | Тело валидное, конфликт с состоянием ресурса; форме надо отличать «занят» от «неверный ввод»                                                                                                                                       |
| В e2e каждый тест регистрации — свой email                                      | Стор в памяти общий на весь файл: общий email сделал бы тесты зависимыми от порядка                                                                                                                                                |
| Участники встречи — `String[]` email, а не связь с `User`                       | Видит их только владелец, приглашённый не обязан быть зарегистрирован; таблица-связка понадобится, когда участникам дадут доступ к встрече                                                                                         |

## Что помнить про окружение

- **`JWT_SECRET` обязан совпадать** в `apps/api/.env` и `apps/web/.env.local`, иначе middleware не проверит токен и вход зациклится.
- Данные живут в Postgres и переживают перезапуск. На пустой БД нужен `pnpm --filter @video-meetings/api db:seed` — при старте приложения сид больше не накатывается. Тестовые аккаунты: `demo@example.com` и `anna@example.com`, пароль `password123`.
- Без поднятого Postgres (`docker compose up -d`) API не стартует: `PrismaService` падает на `$connect()`.
- `DATABASE_URL` нужен в `apps/api/.env`; в `apps/api/.env.test` он указывает на отдельную БД для тестов.
- `pnpm dev` не поднимется, если на портах 3000/3001 висят процессы с прошлого запуска.
- В `apps/api/src/auth/auth.module.ts` есть осознанный `as` для `signOptions`: `jsonwebtoken` типизирует `expiresIn` шаблонным литеральным юнионом, значение из конфига его статически не удовлетворяет.

## Как проверить, что всё живо

```bash
pnpm lint && pnpm typecheck && pnpm test && pnpm build
pnpm --filter @video-meetings/api test:e2e
pnpm dev     # http://localhost:3000/auth/login (нужен поднятый Postgres)
```

Ожидаемо: 8 unit-тестов и 47 e2e-тестов проходят, lint и typecheck чистые.

Браузерную проверку агент делает через Playwright MCP (см. «Сделано § 7»). Как npm-зависимость Playwright в проекте не установлен, и ставить его не нужно.
