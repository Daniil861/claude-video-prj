# PRD: Загрузка файлов во встречу

**Дата**: 2026-10-05
**Статус**: Draft

## Цель

Владелец встречи хранит рядом с ней запись (видео/аудио) и материалы (документы, изображения): загружает, смотрит и скачивает их на странице встречи. Сохранённые файлы — основа для будущей обработки (транскрипт, саммари), которая делается отдельной фичей.

## Пользовательские сценарии

- Пользователь открывает встречу из списка на главной -> видит страницу `/meetings/:id` с названием, датой, длительностью, участниками и блоком «Файлы».
- Пользователь выбирает один или несколько файлов на странице встречи -> по каждому файлу видит прогресс загрузки в процентах; после загрузки файл появляется в списке без перезагрузки страницы.
- Пользователь нажимает «Отменить» во время загрузки -> загрузка прерывается, файл не появляется в списке и не остаётся на сервере.
- Пользователь выбирает файл неподдерживаемого типа или больше 100 МБ -> видит сообщение с причиной до начала загрузки, файл не отправляется.
- Пользователь открывает загруженную запись -> воспроизводит видео или аудио в браузере, перематывает на любой момент.
- Пользователь открывает загруженный PDF или изображение -> просматривает его в браузере, не скачивая.
- Пользователь нажимает «Скачать» -> получает файл с исходным именем и содержимым.
- Пользователь удаляет файл и подтверждает действие -> файл пропадает из списка и больше недоступен по прямой ссылке.
- Пользователь открывает чужую или несуществующую встречу либо её файл -> получает «не найдено», без признаков того, что объект существует.
- Пользователь удаляет встречу (в будущем) или аккаунт -> файлы встречи удаляются вместе с ней.

## В скоупе

- Страница встречи `/meetings/:id` (web): детали встречи и блок «Файлы»; переход на неё из списка встреч на главной.
- Загрузка нескольких файлов за раз во встречу, выбор через диалог и перетаскиванием (drag-and-drop).
- Поддерживаемые типы:
  - записи: `mp4`, `webm`, `mov`, `mp3`, `m4a`, `wav`, `ogg`;
  - документы: `pdf`, `docx`, `pptx`, `xlsx`, `txt`, `md`;
  - изображения: `png`, `jpg`/`jpeg`, `webp`.
- Лимит размера — 100 МБ на файл, до 20 файлов на встречу. Проверка на клиенте (до отправки) и на сервере.
- Прогресс загрузки по каждому файлу и отмена каждой загрузки отдельно.
- Список файлов встречи: имя, тип, размер, дата загрузки, статус обработки; новые первыми.
- Встроенный просмотр: плеер для видео и аудио с перемоткой, просмотр PDF и изображений. Для `docx`/`pptx`/`xlsx`/`txt`/`md` — только скачивание.
- Скачивание файла с исходным именем.
- Удаление файла с подтверждением.
- Доступ к файлам только у владельца встречи; чужая или несуществующая встреча/файл — 404.
- Поле статуса обработки у файла (`uploaded` при загрузке) — задел под будущую обработку. В этой фиче статус не меняется.
- E2E-тесты API на загрузку, список, скачивание, удаление, лимиты, типы и доступ.

## Не в скоупе

- Любая обработка содержимого: транскрипция, саммари, извлечение текста, превью-миниатюры, перекодирование видео.
- Доступ к файлам для участников встречи и публичные ссылки — участники пока только email без доступа к встрече.
- Возобновление прерванной загрузки после обрыва связи или закрытия вкладки.
- Переименование файла и замена его новой версией.
- Предпросмотр `docx`/`pptx`/`xlsx`.
- Квоты на пользователя в целом и биллинг хранилища.
- Антивирусная проверка файлов.
- Запись встречи прямо из браузера.
- Форма создания встречи `/meetings/new` — отдельная задача.

## Технические ограничения

- **Server Actions не подходят для передачи файлов до 100 МБ**: у них лимит тела запроса (по умолчанию 1 МБ) и нет событий прогресса. Решение «Server Actions вместо route handlers» для загрузки файлов придётся пересмотреть и зафиксировать в PROGRESS.md.
- **JWT лежит в httpOnly cookie** и недоступен браузерному JS, а API принимает `Authorization: Bearer`. Загрузка, скачивание и воспроизведение из браузера должны аутентифицироваться без раскрытия токена в JS.
- Файлы не должны держаться в памяти процесса API целиком — 100 МБ на запрос при нескольких параллельных загрузках.
- Хранилище файлов должно переживать перезапуск API и согласованно удаляться с метаданными: отменённая загрузка и удалённый файл не оставляют «сирот».
- Перемотка в плеере требует, чтобы отдача файла поддерживала частичные запросы (HTTP Range).
- Тип файла проверяется на сервере, а не только по расширению от клиента.
- Имя файла от пользователя не должно влиять на путь хранения и ломать заголовок скачивания (кириллица, пробелы, `../`).
- E2E работают с отдельной БД `video_meetings_test` и чистят её; файлы тестового прогона не должны смешиваться с файлами разработки.
- Тесты только на API; UI проверяется в браузере (Playwright MCP) по чек-листу `apps/web/CLAUDE.md`.
- Сейчас `docker-compose.yml` поднимает только Postgres; новое внешнее хранилище, если понадобится, добавляется туда же и в README.

## Критерии готовности

- [ ] Из списка встреч на главной открывается `/meetings/:id` с названием, датой, длительностью и участниками встречи.
- [ ] Чужая и несуществующая встреча на `/meetings/:id` показывают «не найдено»; API отвечает 404 на встречу, список, скачивание и удаление файлов чужой встречи.
- [ ] Файл каждого поддерживаемого типа загружается и появляется в списке с именем, типом, размером, датой и статусом `uploaded`.
- [ ] Файл 100 МБ загружается успешно; файл 100 МБ + 1 байт отклоняется на клиенте до отправки и на сервере (если отправлен в обход клиента).
- [ ] Неподдерживаемый тип (например, `.exe`) и файл с подменённым расширением отклоняются сервером с понятной ошибкой.
- [ ] 21-й файл во встречу отклоняется с сообщением о лимите.
- [ ] При одновременной загрузке трёх файлов у каждого виден свой прогресс; отмена одного не прерывает остальные.
- [ ] Отменённая загрузка не появляется в списке, и после неё на сервере не остаётся данных файла.
- [ ] Загруженное видео и аудио воспроизводятся на странице встречи, перемотка в середину файла работает без полной загрузки.
- [ ] PDF и изображения открываются для просмотра в браузере.
- [ ] Скачанный файл побайтно совпадает с загруженным и сохраняется с исходным именем, включая кириллицу и пробелы.
- [ ] После удаления файл пропадает из списка, а его прямая ссылка отвечает 404.
- [ ] Удаление пользователя удаляет его встречи вместе с файлами — в хранилище не остаётся данных.
- [ ] Загруженные файлы доступны после перезапуска API.
- [ ] Без аутентификации все эндпоинты файлов отвечают 401; токен не появляется в JS страницы и в URL.
- [ ] Страница встречи проверена в браузере на 1280 и 375 px в светлой и тёмной теме: загрузка, прогресс, отмена, ошибки, плеер, скачивание, удаление, пустое состояние «Файлов пока нет».
- [ ] E2E на файлы проходят вместе с существующими; `pnpm lint && pnpm typecheck && pnpm test && pnpm build` чистые.
- [ ] README (маршруты, эндпоинты, env), PROGRESS.md и `.env.example` обновлены, решение о способе загрузки файлов записано в «Принятые решения» с причиной.
