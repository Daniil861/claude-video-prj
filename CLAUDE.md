# CLAUDE.md

Монорепозиторий `video-meetings`: pnpm workspaces + Turborepo, два приложения и два пакета общих конфигов.

## Обязательное перед началом и в конце работы

- **Читай [PROGRESS.md](PROGRESS.md) в начале сессии** — это файл-хендофф: что сделано, что дальше, какие решения приняты и почему. Технические детали запуска — в [README.md](README.md).
- **Обновляй PROGRESS.md при каждом заметном шаге** (новая фича, изменение архитектуры, новое решение) — раздел «Сделано», «Дальше», таблицу «Принятые решения».
- **Меняешь архитектуру — обновляй документацию в том же коммите.** Правила ниже.
- Документация проекта ведётся **на русском языке**. Комментарии в коде и docstring — на английском (см. существующий код).

## Актуализация документации при изменении архитектуры

Документация — часть изменения, а не отдельная задача «на потом». Если правка меняет то, что описано в документе, документ правится **в том же коммите**. Расхождение между кодом и документом хуже, чем его отсутствие: следующая сессия начнёт с неверной картины проекта.

**Что считается изменением архитектуры** (не каждая правка кода):

- добавлен, удалён или переименован эндпоинт API, маршрут Next, модуль Nest или фичевый модуль в `src/features`;
- изменился контракт между web и api (форма ответа, коды ошибок, заголовки, способ аутентификации);
- сменился способ хранения данных, кэширования, работы с сессией или конфигурацией;
- добавлена, удалена или заменена зависимость, влияющая на подход (ORM, UI-библиотека, тест-раннер, валидация);
- изменились скрипты, переменные окружения, порты, структура папок или общие конфиги в `packages/`;
- принято решение, отменяющее или заменяющее одно из «Принятых решений».

**Что обновлять:**

| Изменение                                                     | Куда                                                                       |
| ------------------------------------------------------------- | -------------------------------------------------------------------------- |
| Любое из списка выше                                          | `PROGRESS.md` — «Сделано», при необходимости «Дальше» и «Принятые решения» |
| Новый или изменённый эндпоинт, маршрут, скрипт, шаг установки | `README.md` — таблицы маршрутов и скриптов                                 |
| Правило или ловушка, специфичные для приложения               | `apps/web/CLAUDE.md` или `apps/api/CLAUDE.md`                              |
| Общее правило, команда, соглашение, переменная окружения      | этот файл                                                                  |
| Новая или изменённая переменная окружения                     | соответствующий `.env.example` **и** таблица env в CLAUDE.md приложения    |

**Как обновлять:**

- Решение фиксируется вместе с **причиной** — в таблице «Принятые решения» в PROGRESS.md. Строка без объяснения «почему» бесполезна.
- Отменённое решение не удаляется молча: замени формулировку и укажи, что пришло на смену.
- Если пункт из «Дальше» сделан — перенеси его в «Сделано», а не оставляй в обоих разделах.
- Не дублируй один и тот же текст в нескольких файлах — ставь ссылку. README — про запуск, PROGRESS — про состояние и решения, CLAUDE.md — про правила работы с кодом.
- В конце работы сверься: изменившиеся файлы против списка выше. Если код поменялся, а ни один документ — нет, объясни в ответе почему.

## Структура

```
apps/
  web/                Next.js 16, App Router  — http://localhost:3000       (см. apps/web/CLAUDE.md)
  api/                Nest.js 11              — http://localhost:3001/api   (см. apps/api/CLAUDE.md)
packages/
  eslint-config/      flat-конфиги: base / next / nest
  typescript-config/  base.json / nextjs.json / nestjs.json
```

`eslint-config-next` живёт в `packages/eslint-config` — его версию бампать вместе с версией Next.

## Команды

Все команды запускаются из корня через Turborepo:

```bash
pnpm dev            # web + api параллельно
pnpm dev:web        # только Next.js
pnpm dev:api        # только Nest.js (watch)
pnpm lint           # ESLint по всем пакетам
pnpm typecheck      # tsc --noEmit по всем пакетам
pnpm test           # unit-тесты (фактически только apps/api), БД не нужна
pnpm build
pnpm format         # Prettier
```

Адресно: `pnpm --filter @video-meetings/api <script>`, `pnpm --filter @video-meetings/web <script>`.

**Проверка перед коммитом:**

```bash
pnpm lint && pnpm typecheck && pnpm test && pnpm build
pnpm --filter @video-meetings/api test:e2e
```

Ожидаемо: 8 unit- и 28 e2e-тестов проходят, lint и typecheck чистые. E2E требуют поднятого Postgres и работают с отдельной БД `video_meetings_test`.

## Окружение

- Node.js >= 20.11, pnpm 11 (`corepack enable pnpm`).
- Env — **по приложению**, а не один корневой: Next не читает корневой `.env`.
  - `apps/api/.env` ← `apps/api/.env.example`
  - `apps/web/.env.local` ← `apps/web/.env.example`
  - корневой `.env` — только для docker-compose.
  - `apps/api/.env.test` — БД для e2e; лежит в репозитории, секретов не содержит.
- **`DATABASE_URL` обязателен в `apps/api/.env`** — без него `PrismaService` падает при старте.
- **`JWT_SECRET` обязан совпадать** в `apps/api/.env` и `apps/web/.env.local`, иначе middleware не проверит токен и вход зациклится.
- `docker-compose.yml` поднимает Postgres 16 — **API без него не стартует**. На пустой БД нужны `db:deploy` и `db:seed` (см. README).
- `pnpm dev` не поднимется, если на портах 3000/3001 висят процессы с прошлого запуска.

## Соглашения

- **Коммиты — Conventional Commits**, проверяются commitlint через хук `commit-msg`. lint-staged прогоняет Prettier по staged-файлам.
- Prettier: одинарные кавычки, точки с запятой, trailing comma `all`, printWidth 100, 2 пробела. Не форматируй руками — `pnpm format`.
- **Форматирование автоматическое на двух рубежах:** хук Claude Code `PostToolUse` (`.claude/settings.json` → `.claude/hooks/format-file.mjs`) прогоняет Prettier сразу после правки файла, а husky `pre-commit` → lint-staged — перед коммитом. Скрипт работает только с файлами внутри репозитория и молча выходит, если payload неожиданный или Prettier не установлен. Посмотреть или отключить хук — команда `/hooks`.
- TypeScript strict, включая `noUncheckedIndexedAccess`. `any` не использовать; для внешних данных — `unknown` + сужение (см. `apps/web/src/lib/api.ts`).
- `no-console` — предупреждение, разрешены только `warn`/`error`. В Nest используй `Logger`.
- Переносы строк — LF (`.gitattributes`).

## Архитектурные решения (не менять без обсуждения)

| Решение                                                  | Почему                                                                                                                               |
| -------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| Postgres через Prisma 7, доступ только из сервисов       | Отменяет прежнее «данные в памяти»: расчёт на замену внутренностей сервисов оправдался — контроллеры получили лишь `Promise` в типах |
| Отдельная БД `video_meetings_test` для e2e               | Прогон чистит и засевает таблицы; на общей БД он стирал бы данные из браузера                                                        |
| JWT в httpOnly cookie, а не localStorage                 | Токен недоступен браузерному JS; главная — server component                                                                          |
| Server Actions вместо route handlers в Next              | Меньше слоёв: нет промежуточного `/api/...` в Next                                                                                   |
| Свой `JwtAuthGuard` вместо passport-jwt                  | ~20 строк вместо трёх зависимостей и стратегий                                                                                       |
| Middleware проверяет подпись и срок, а не наличие cookie | Иначе просроченный токен зацикливает редиректы                                                                                       |
| Тесты только на API                                      | Фронт проверяется вручную/браузером                                                                                                  |

Полный список с контекстом — в PROGRESS.md.
